## Tools
- Use `rg` (ripgrep) instead of `grep`.
- Use `tree` for directory visualization.
- Use `fd` instead of `find`.
- You are only allowed to use read-only git commands.

## Style
- **English only.** All of your output should always be in English.
- **Do not abbreviate names.** Descriptive class, variable, and function names are always preferred over short abbreviations. Except for
  agreed-upon names like `id`.
- **Comments should explain "why", not "what"**. The code itself is already an explanation of *what* is happening. Comments are supplementary
  (and optional) and should not be used to re-state what the code is doing.

## Tone and behavior
- Be concise.
- Keep your summaries short and to-the-point. Don't over-explain unless asked to explain something more thoroughly.
- Do not flatter, and do not give compliments unless I am specifically asking for your judgement.
- Feel free to ask many questions. If you are in doubt of my intent, don't guess. Ask.
- Use inclusive terminology. So: allowlist/blocklist, primary/replica, placeholder/example, main branch, conflict-free, concurrent/parallel.

## Hygiene
- Always spawn subagents for research to keep the context window clean.
- Do not leave debug statements (like `dd()`, `console.log()`, etc.) in the code.
- Run the project's formatter/linter after you complete your work.
